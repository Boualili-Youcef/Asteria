    04 / ÉCHOUER SOUS CONTRÔLE
    Le rollback doit
    se vérifier aussi.
    Le scénario préparé change uniquement une readiness probe dans le namespace de démo. Sa validation réelle sur K3s reste un critère distinct.
    
      
    
      
    Version saine→Probe invalide→Échec détecté→Rollback + /ready
    
      
    TESTS LOCAUX
    Garde-fous testés
    Mauvais cluster, dépôt inattendu et digest invalide sont refusés. Les tests simulent une erreur Helm ou de probe et exigent la vérification de l'image précédente. Ce sont des tests du script, pas une panne K3s observée.
    NON VALIDÉ SUR K3S
    La preuve live reste à produire
    Un déploiement et son rollback nécessitent un périmètre autorisé, des données synthétiques isolées et des droits bornés. Aucun succès n'est présumé. Le lab ne revendique ni HA, ni DR, ni exploitation de production.
